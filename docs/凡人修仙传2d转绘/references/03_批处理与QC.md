# 批处理与 QC

## 串行批处理原则

manifest 建议字段：

```text
segment,index,source_video,description_txt,duration_seconds,
h3_fps,h3_length,h3_width,h3_height,seed,status,prompt_id,
storyboard_path,h3_ai_video,final_video,updated_at,notes
```

状态使用：`pending`、`storyboard_done`、`h3_submitted`、`h3_done`、`audio_done`、`qc_pass`、`failed`。每完成一个原子步骤就写回 manifest；不能等全批结束再补记。

续跑时不能只看文件是否存在：必须同时确认文件可解码、规格、时长、音轨和 QC。已有合格片段可以跳过；失败文件保留并使用 `_failed_YYYYMMDD_HHMMSS` 版本名。

H3 提交必须是：

```text
检查 server/queue → 提交 1 段 → 保存 prompt_id → 轮询到 success/error
→ 复制 H3 输出 → 原音替换 → 技术 QC → 视觉 QC → 更新 manifest → 下一段
```

单段脚本调用示例：

```powershell
python scripts/build_h3_assets.py `
  --project-root "<project_root>" --segment Merge-001 `
  --source-video "<source.mp4>" --storyboard "<storyboard.png>" `
  --base-workflow "<api_workflow.json>" `
  --comfy-input "<ComfyUI>\input" --style-lock "<project_root>\style_lock.md" `
  --style-tag "user_style_v1" --seed 20260001

python scripts/submit_and_wait_h3.py `
  --workflow "<workflow.json>" --segment Merge-001 `
  --log "<segment>\storyboard_process\logs\prompt_id.txt"

python scripts/finalize_video.py `
  --segment Merge-001 --ai-video "<h3.mp4>" `
  --source-video "<source.mp4>" --output "<final.mp4>"
```

## ComfyUI API 最小检查

本地默认地址：`http://127.0.0.1:8188`。

```powershell
Invoke-RestMethod 'http://127.0.0.1:8188/system_stats'
Invoke-RestMethod 'http://127.0.0.1:8188/queue'
```

Workflow 必须是 API JSON，不是编辑器导出的 `nodes`/`links` 格式。参考图输入只保留当前片段无台词故事板。workflow 送入未知自定义节点前，先检查节点和模型依赖。

## 单片段技术阈值

- 视频：`1376×768`、`24/1 fps`；
- 视频和音频都能被 ffprobe 读取；
- `ffmpeg -v error -xerror -i final -f null -` 无错误；
- 有且仅有可解码源音频轨；
- 最终时长与源片段足够接近，实际阈值按项目设定，默认不超过 `0.12 s`；
- 源音频与最终音频解码到相同 PCM 后 SHA256 一致；
- 最终文件不是 H3 音频版本。

## 12 帧视觉 QC

均匀抽取首帧、尾帧和中间帧，拼成 4×3 或 3×4 网格。检查：

1. 是否保持 `style_lock.md` 中的风格、二维表达和画面可读性；
2. 是否出现黑尾、泥黑过曝、无意义暗场或闪烁；
3. 是否出现任何字幕、中文、乱码、竖幅书法、面板边框、数字、水印或 logo；
4. 人物脸型、发型、服装主色、左右关系和关键道具是否稳定；
5. 动作是否连贯，是否只是静态图慢推；
6. 是否丢 Shot、换顺序、改变主要动作或加入新剧情。

重大失败不得标记 `qc_pass`。如果是文本或暗场问题，优先修改故事板/H3 prompt 后重生成；如果是时长/音轨/解码问题，修正封装流程并重跑 QC。

## 全批 QC 和全集拼接

运行 `scripts/batch_qc.py` 生成 JSON/CSV 汇总。只有全部通过后才运行：

```powershell
python scripts/concat_videos.py `
  --input-root "<project_root>" `
  --pattern "Merge-{index:03d}/Merge-{index:03d}_user_style_v1_H3_768p_原声音轨_v1.mp4" `
  --start 1 --end 55 `
  --output "<project_root>/全集_user_style_v1_768p_v1.mp4"
```

拼接脚本使用 concat demuxer 做无损封装合并；所有输入必须编码、尺寸、帧率和音频参数一致。全集生成后仍需跑完整 ffmpeg 解码检查，并记录总时长、文件大小和最终路径。
