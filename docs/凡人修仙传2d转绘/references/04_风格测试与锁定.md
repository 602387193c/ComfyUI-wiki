# 风格测试与锁定

## 目标

把“我想要某种感觉”变成可重复执行的风格规范。全量生成前必须有一个用户看过的小样；小样不是试错记录，而是为全量生产确定风格、质量门槛和禁止项。

## 1. 先收集用户的风格意图

至少确认：

- 参考作品、参考图或文字描述；
- 是否必须保持 2D 手绘、赛璐璐、厚涂、版画、纸片、剪纸等媒介特征；
- 线条、阴影、色彩、材质、背景密度、光线和镜头运动的偏好；
- 画面是否偏明亮、低饱和、强对比、暗黑或其他明度目标；
- 是否允许保留原片的夸张动作、镜头语言和角色造型；
- 试验分辨率、时长、是否保留原音；
- 明确禁止的内容：文字、字幕、水印、3D、写实、过密细节、闪烁等。

如果用户只给了一个作品名，不要直接把作品的具体画面当作生成参考。先把它转成可执行的高层描述，例如“梦境式跳切、平面色块、线条粗细、色彩对比、背景留白、动作节奏”，再让用户确认。

## 2. 选择测试片段

优先选：

1. 有清楚人物和动作的代表性片段；
2. 能体现用户关注的风格特征的片段；
3. 如果项目包含战斗、近景对白、群像或复杂场景，再补一个最难片段。

不必一开始测试全部片段。通常 1 个代表片段足够确定方向，第二个复杂片段用于验证风格能否跨场景稳定。

## 3. 小样的迭代顺序

每一轮只改变一个主要变量，避免不知道为什么变好或变坏：

1. 先确定故事板是否准确：人物、镜头顺序、动作和关键道具；
2. 再确定画面媒介：线条、阴影、色块、材质和背景密度；
3. 再确定色彩和明度：主色、强调色、对比度、暗部保留；
4. 最后确定 H3 动画性：动作连续度、镜头运动、节奏和表演。

每轮保留：输入、故事板、H3 prompt、workflow、seed、输出视频、用户反馈。文件使用 `test_v1`、`test_v2` 等版本，不覆盖上一轮。

## 4. 向用户展示小样时应说明

每个小样配一段简短说明：

```text
测试版本：style_test_v2
保留：人物身份、原镜头顺序、原动作节奏、原声音
本轮变化：粗线条 + 两阶阴影 + 低饱和蓝灰背景
请确认：风格方向、画面明度、细节密度、动作连续性
```

不要把“技术上能生成”当作“风格已经确认”。用户确认应明确指向某个版本，或明确说“按这个风格继续”。

## 5. 写入 style_lock.md

用户确认后，在项目根目录保存：

```markdown
# Style Lock

- style_id: user_style_v1
- approved_test: Merge-001/style_test_v2
- approved_at: YYYY-MM-DD HH:MM
- user_goal: [用户原话的风格目标]

## Positive visual language
- medium/line:
- shading:
- palette:
- lighting/value:
- background/detail density:
- composition/negative space:
- motion/editing:

## Negative constraints
- [禁止项]

## Production constants
- output: 1376x768 @ 24fps
- audio: original source audio
- H3 reference: clean storyboard only

## Allowed local corrections
- [只影响某个片段的局部修正]

## Re-test triggers
- 改变整体媒介、色板、明度、线条或运动语言；
- 用户反馈风格不对；
- 测试片段能通过但复杂片段明显失效。
```

## 6. 锁定之后的变更规则

锁定后，所有片段必须引用同一份 `style_lock.md` 和同一版本风格锚点。可以修正单个片段的镜头理解、文本残留、人物连续性或局部曝光，但不能悄悄改变整体风格。

如果用户后来改变整体方向，建立 `style_v2`，重新选择代表片段测试并得到确认；不要直接用新风格覆盖已经生成的全量结果。
